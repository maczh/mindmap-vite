# 2026-10-03 追加：手绘质感重做 + 概要自动定向

## 问题 1：手绘主题太丑（用户反馈「应改成艺术家炭笔风格，线条要流畅」）

### 根因诊断
初版用 `noise2(seed, i, j)` **逐点独立随机偏移** —— 这是**高频噪声**，
画出来是锯齿（信号干扰感），不是人手运笔。
炭笔的质感来自**低频、连续、可预测的起伏**：整体走势稳定，只在中段缓慢摆动。

### 解决方案：谐波叠加代替逐点随机
新增 `wobble(seed, amp, t, anchor)`：
```
offset(t) = Σ wₖ·sin(2π·fₖ·t + phaseₖ)   f = [0.5, 1, 1.5], w = [1, 0.45, 0.22]
```
- 低频 → C∞ 连续，视觉上就是流畅的一笔
- 相位由种子决定 → 仍是确定性的（不用 Math.random）
- `anchor="both"` 用 `sin(πt)` 包络让**两端归零、中段最大**（起笔稳、中段飘、收笔稳），
  保证连线端点仍精确接在节点边缘
- 振幅按线长缩放（`len/90`，clamp 0.7~2.2），短线不会抖成毛刺、长线也有力度
- `handLine` 采样数 4 → 10

### 踩坑：Catmull-Rom vs 中点二次贝塞尔
最初用 `Q cur mid(cur,next)` 想把折线磨圆 —— **这是错的**：
该写法会把曲线拉直，转角变成**折线尖角**，画出来是「切角矩形」，完全不像手绘。
正确做法是 **Catmull-Rom 转贝塞尔**，控制点 `c1 = p1 + (p2-p0)/6`、`c2 = p2 - (p3-p1)/6`。

### 踩坑：转角必须有采样点
只改 Catmull-Rom 仍不够 —— 初版 `handRect` 只在**四条直边**上采样，
转角区域一个采样点都没有，Catmull-Rom 只能跨 90° 插值 → 仍是尖角。
修法：显式生成「直边 + 四分之一圆弧」交替的采样序列
（`pushEdge` 7 点/边、`pushArc` 5 点/角，共 48 点），再统一 Catmull-Rom 闭合。
`handEllipse` 同样改用 Catmull-Rom 闭合。

### 振幅参数下调
炭笔要含蓄，振幅大就变折线毛刺：
手绘彩色 1.6→**1.1**、手绘蓝图 1.3→**0.9**、手绘森野 2.0→**1.3**

## 问题 2：概要应根据节点朝向自动左/右定位

### 规则（对齐用户截图）
- 节点在画布**右半边** → 概要放**最左边**（括号开口朝右，抱住节点）
- 节点在**左半边** → 概要放**最右边**（括号开口朝左）
- 判断依据：被汇总节点包围盒中心 vs 整张画布中心
- 节点居中时兜底放右侧

### 符号约定（这次绕了弯路，务必记牢）
`side` **就是概要摆放方向**，所有位移一律写成 `outerEdge + side * k`：
```ts
const outerEdge = side === 1 ? b.x + b.w : b.x;  // 朝向概要的那条边
let braceX = outerEdge + side * GAP;
const waistOff = -side * bulge;                   // 腰部朝节点侧凸出
const boxXFor = (bx) => {                          // 返回框的【左边缘】
  const inner = bx + waistOff + side * 22;
  return side === 1 ? inner : inner - labelW;     // ← 向左摆放必须再减框宽
};
```
三个曾经的 bug：
1. `outerEdge` 取反了边（side=-1 时取了右缘）→ 概要跑到节点外侧
2. `boxXFor` 向左时返回的是框的**右边缘**却当左边缘用 → 差一个 labelW
3. 循环里 `waistX` 用了循环外的旧值 → ReferenceError

### 括号形状
腰部凸向**节点**一侧（`-side * bulge`），形成「抱住节点」的姿态，
而不是简单的「一律凸向右」。

## 第七轮：概要弧线「双瓣」→「单条 C 弧」

方向修对后，用户指出弧线形状仍错。放大截图后确认：灰线在**腰部（引线接出处）向内凹出尖角**，
鼓包被挤到上下两端，视觉上是个「B」形双瓣，而不是一条 `C`。

### 根因（贝塞尔控制点放错位置）

```diff
- C ${bellyX} ${topY}, ${bellyX} ${midY}, ${tipX} ${midY}   // 中点收回 tipX → 腰部内凹
+ C ${bellyX} ${topY}, ${bellyX} ${midY}, ${bellyX} ${midY}   // 中点落在 bellyX → 唯一鼓包
```

旧写法把**中点**设成 `tipX`（节点侧），于是腰部往内收、鼓包跑到两端。
正确写法：两段的控制点**都放在腰线上**，腰部（t=0.5）恰好落在 `bellyX`，
两段在腰部同为竖直切线 → 接缝处切线连续，视觉上就是一条整弧。

### 附带调整
`BELLY` 由固定 15 改为随组高自适应：`clamp(组高 × 0.34, 10, 34)`。
组高 101px 时鼓包 34px（原来 15px 太扁，这也是「看起来像两瓣」的帮凶）。

### 验证
`verify/summary-geom.ts` 33 项全通过（新增 2 项）：
- `腰部中点 = 鼓包位置（单弧，非双瓣）`：`anchors[1].x === bellyX`（右组 1036 / 左组 -36）
- 原有的「腰部朝框鼓出」断言保留，两者互为对照

### 有效的调试手法（值得复用）
肉眼反复裁剪窗口容易失焦。**更快的办法**：从 SSR 出的 SVG 里正则抓 path 的
14 个贝塞尔参数，直接打印「上尖 / 腰 / 下尖」三个关键点 + 鼓包量，一眼定形。
再用 resvg 把 `mm-extras` 图层**隔离**出来放大 10 倍（`viewBox` 卡住包围盒），
完全不受节点遮挡影响 —— `verify-shots-20261003/27-summary-arc-isolated.png`。
