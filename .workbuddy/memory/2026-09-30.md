## 节点样式改造：层级字号 + 下划线风格 + 鱼骨图文字不旋转

**需求**：① 所有结构样式中根节点字号最大、一级次之、二级及叶子最小，且无外边框、下划线风格；② 鱼骨图文字不旋转，正常从左到右。

**改动**（youdao-mindmap-vite）：
- `src/components/MindMap/layout.ts`
  - 新增 `defaultFontSizeForDepth(depth)`：0→24 / 1→18 / 其余→14。
  - `nodeSize(node, depth = 0)` 用层级默认字号；`makeSizer(depthMap)` 接收层级映射。
  - `layoutTree()` 先遍历树生成 `depthMap`（不改节点数据），供测量用；渲染侧用 `p.depth`。
  - 鱼骨图：`n.rot = 0`（去掉 `boneDeg`/`rotFor`），节点仍按骨头方向定位。
- `src/components/MindMap/MindMap.tsx`
  - `const shape = eff.shape ?? "underline"`（下划线＝无 rect + 画下划线）。
  - 渲染字号 `eff.fontSize ?? defaultFontSizeForDepth(p.depth)`；编辑框同理。
  - **连带修复**：根节点文字色 `theme.rootText`（经典主题为白色，配填充色块）在不绘制色块时不可见 → 改为 `isRoot && showRect ? rootText : nodeText`。

**验证**：`vite --port 5179` + agent-browser 断言：字号分布 `{24:1,18:5,14:14}`；无任何 `rect.mm-rect`；全部有 `line.mm-underline`；鱼骨图 `anyRotate=false`。`npx tsc -b` 通过。预览图存 `node-style-shots/`。

**结论/经验**：本仓库默认「填充色块 + 白字」主题，一旦把默认形状改为下划线（无底色），必须同步把文字色从 `rootText` 回退到 `nodeText`，否则白字白底不可见。字号若要影响版式，必须同时进测量（sizer）与渲染，仅改渲染会撑破文字框。

## 节点样式改造（续）：根节点与一级节点加外框

**需求**：所有结构样式中，根节点与一级节点加外框（带边框色块），其余层级保持下划线风格。

**改动**：`src/components/MindMap/MindMap.tsx` 节点渲染处，形状默认值由「全局 underline」改为按层级：
```ts
const defaultShape = p.depth <= 1 ? "rect" : "underline";
const shape = eff.shape ?? defaultShape;
```
- `depth<=1`（根 24px + 一级 18px）→ `rect`（圆角边框；根填充主色 + 白字，一级浅底 + 深字）。
- `depth>=2` → `underline`（无边框，仅下划线）。
- 逐节点显式 `style.shape` 覆盖仍生效。
- 同步更新 `layout.ts` 中 `defaultFontSizeForDepth` 的注释（原文写「无外边框」已过时）。
- **无需改布局**：`nodeSize()` 尺寸与形状无关，加框不改变节点盒子大小。

**验证**：`vite --port 5180` + agent-browser：默认结构与鱼骨图均为 `framed=6`（24×1+18×5）、`underlined=14`（14px）、鱼骨 `anyRotate=false`；`npx tsc -b` 通过。预览图 `node-style-shots/{default-structure,fishbone}.png`；报告 `NODE_FRAME_REPORT.md`。

**经验**：所需「少数层级差异化」用 `depth` 阈值改默认形状最省事——测量层不动，仅渲染层一行三元；切忌去改节点数据。

## 节点样式精修：叶子下划线「轨道」仿截图 + 胶囊外框 + 禁止自动换行

**需求（3 件）**：① 二级及以下 / 叶子节点样式仿参考截图（文字左对齐 + 下划线，连线自下划线接入）；② 根 / 一级外框改为**胶囊**；③ 所有节点（含叶子）**不允许自动换行**。

**改动**（youdao-mindmap-vite）：
- `MindMap.tsx` 叶子「下划线轨道」：
  - 新增模块级常量 `UNDER_LEFT=12 / UNDER_PAD_R=6 / UNDER_DY=7`，以及 `underlineTextWidth(n)`（用 `measureText` 取最宽行宽）与 `underlineRail(n)`（左端 / 右端 / y，绝对坐标）、`isUnderlineNode(n)`（含 shape 覆盖判断）。
  - 渲染：下划线 `x1=UNDER_LEFT`、`x2=UNDER_LEFT+prefixWidth+textW+UNDER_PAD_R`（贴合文字、非整个盒子宽），文字 `textAnchor="start"`，`x=UNDER_LEFT+prefixWidth`。
  - `linkPath()` 水平轴：两端点若为下划线节点则落在轨道两端（`y = n.y+n.h-UNDER_DY`），带框节点仍取边缘中点 → 线条与下划线连贯。v/diag 轴不动。
  - **连带修复**：渲染里 `nodeSize(node)` 漏传 depth（多行节点行距按 24px 算），改为 `nodeSize(node, p.depth)`。
- `layout.ts` 禁止自动换行：`nodeSize()` 里 `wrapText(..., Number.POSITIVE_INFINITY, ...)`（只禁宽度折行，仍保留 `\n`），去掉 `Math.min(..., MAX_TEXT_W+extra)` 上限并删除 `MAX_TEXT_W` 常量。
- `MindMap.tsx` 层级默认形状 `depth<=1` 由 `rect` → `capsule`（复用既有 `rx=p.h/2`）。

**踩坑**：最初把下划线画成「整个节点盒宽」，多行节点在较短末行下会拖出很长一段孤立线（鱼骨图里尤其明显）；改成贴合**最宽行**的宽度即解决。另外 `railTextW` 曾放在 `isUnderline` 声明前 → TS2448，需注意声明顺序。

**验证**：`vite --port 5181` + agent-browser：默认 / 鱼骨 / 时间轴均为 `boxed=6`、`capsules=6`（`rx===h/2`）、`maxLines=1`（无自动换行）；下划线 `anchor=start`、`x1=12`、`x2≈12+文字宽`。`npx tsc -b` 通过。预览 `node-style-shots/{default-structure,fishbone,timeline}.png`；报告 `NODE_REFINE_REPORT.md`。

**经验**：下划线「轨道」要贴合**最宽行**而非盒子宽，否则多行节点会出孤立长线；连线的接入点要跟着轨道端点走，否则线与下划线断开。字形宽度用 `measureText`（纯字符估算，SSR 友好）。

## 二级及以下 11px + 与一级交互完全一致（全局，不限 timeline）

**需求**：① 二级及下级 / 叶子节点字号 = 11px，且**新增**的二级及以下节点同样 11px；② 二级及以下的鼠标 + 键盘响应与一级**完全一致**（单击选中 / 双击编辑 / Enter 同级 / Tab 下级 / 右键圆盘菜单）；编辑后按 Enter 完成编辑并新增同级、选定当前节点。

**改动**：
- `layout.ts` `defaultFontSizeForDepth`：二级及以下 `14 → 11`（渲染 + 测量同源）。
- **新增节点字号缺陷修复**（关键）：新建节点有两条路径，都会给新节点写死 `fontSize = DEFAULT_TEXT.fontSize(=14)`，从而**覆盖**按深度的兜底 —— 导致新二级节点是 14、新一级节点也是 14。
  - `MindMap.tsx` `withDefaults()`（全局 Tab/Enter/右键「下级/同级/上级」都走它）→ `fontSize = defaultFontSizeForDepth(depthOf(tree, id))`。
  - `MindMap.tsx` `endEdit()`（编辑态 Enter/Tab 收尾）→ 同样按深度算字号。
  - `tree.ts` 新增 `depthOf(root, id)`（根 0 / 找不到 -1）。
- **交互命中区修复**（关键）：处理器本就挂在每个 `<g class="mm-node">` 上、全深度生效；真缺口是无框节点只有文字字形可点。为 `!showRect` 节点补透明命中矩形 `mm-hit`（`p.w × p.h`, `pointer-events:all`）→ 整节点区域可点/右键/拖拽。
- **编辑态 Enter 语义对齐**：编辑框 `onKeyDown` 由 `Enter → endEdit(null)`（仅提交）改为 `endEdit("sibling")`（提交 + 新增同级），与右键圆盘 `Enter=同级 / Tab=下级` 一致；`endEdit` 创建新节点后 `setEditing(新节点)` 实现连续录入；Shift+Enter 仍换行。

**验证**（`vite@5184` + agent-browser，tl-sample timeline fixture）：root/L1/L2 = 24/18/11px；选中一级「待办」按 Tab → 节点 20→21、**新节点字号 11px**；编辑态回车 → 21→22（新增同级）；二级节点「包厢/散台模型」单击 → 出现 `.mm-ui-only` 虚线框、双击 → `.mm-editor-input`=1、右键 → `.mm-radial` 数量=1、选中后 Tab → +1（新 L3 节点 11px）、Enter → +1（L2 同级）。`npx tsc -b` 通过。

**踩坑 / 经验**：
1. **本机 agent-browser 报 `Failed to create socket directory: Permission denied`** —— 因为 shell 无有效 `HOME`（解析到 `/root` 无权限）。修法：脚本开头 `export HOME=/home/macro; export XDG_RUNTIME_DIR=/tmp`。
2. **截图空白/多图 md5 相同** 的根因不是没渲染，而是**在 Vite 冷启动 transform 完成前就截图**（`curl` 200 只代表 index.html 已返回，ESM 模块图还没请求/执行）。可靠做法：`agent-browser eval "document.querySelectorAll('.mm-node').length"` 轮询到 >0 再截。
3. viteserver 必须与截图**在同一条前台命令**里起停（后台任务结束会被回收）。
4. 新增节点字号这类「全局默认」被「创建时写死的 style」覆盖，是典型暗坑：凡是按层级计算的默认值，新建路径都不能再写死。

**报告**：`NODE_L2_FONT_INTERACTION_REPORT.md`（时间轴报告见 `NODE_TIMELINE_REPORT.md`）。预览 `timeline-shots/{app-timeline,deep-tree,interaction-l2,elbow-detail,compare-reference-vs-result}.png`。可复用脚本 `_verify/{tl-sample,tl-deep}.*`、`_verify/capture.sh`、`_verify/verify-font.sh`。

## 鱼骨图结构样式仿截图重写

**需求**：把 `fishbone` 结构样式模仿参考截图「奇海 RIS 菜品模型」鱼骨图重写（左侧蓝灰实心根 + 水平脊柱 + 45° 斜骨 + 框形一级胶囊被骨穿左 1/4 + 无框二级文字 + 括号三级）。

**改动**（youdao-mindmap-vite）：
- `layout.ts`
  - 新增 `bracketExtent(n)`（深度累加行数，替代旧 `fbRows` 仅数叶子——少算深度是重叠根因）。
  - 重写 `layoutFishbone`：一级盒中心落骨上、右移使骨穿左 1/4（`FB_L1_CROSS=0.25`）；二级沿 45° 骨排开，起步距离 `l2Start=max(FB_L1_DY+FB_SLOT, spineSafe, boxSafe)`——`spineSafe` 防深层括号穿脊柱、`boxSafe` 防首个三级括号压住宽一级盒；`placeBracket` 兄弟间距 `acc+=bracketExtent(c)+1`（旧 `max(1,fbRows)` 让后代与下一兄弟同行重叠）；脊柱/斜骨/括号统一 `FISHBONE_ACCENT` 单色。
  - `layoutFishbone` 形参 `branchColors`/`linkColor` 改名 `_branchColors`/`_linkColor`（单色后未用，避 TS6133）。
- `theme.ts` 新增 `FISHBONE_ACCENT="#73a1bf"`（截图蓝灰 rgb(115,161,191)）。
- `MindMap.tsx` `isFishbone`：根强制 `#73a1bf` 填充 + 白字；一级描边 `#73a1bf`（填充沿用主题白底压住骨）；折叠圆点落骨锚点。节点自身 `color`/`style.borderColor` 仍优先。

**验证**：`_verify/fb-check.mts`（esbuild+node）几何自检 **28 项 ALL PASS，overlaps=0**（修复前 2 处真实重叠：兜底超时↔预订→开台、对接 baseServ↔轮询）；6 种其它结构无回归。`npx tsc -b` 通过。PIL 像素比对：渲染图含 `rgb(115,161,191)`、连续水平脊柱 237px（降采样）、`rootBlue(left)%` 0.0115 vs 参考 0.0074 → 调色板与截图一致。截图 `fb-shots/fishbone.png`（vite@5184 + agent-browser，`_verify/capture-fb.sh`）。

**踩坑 / 经验**：
1. `layoutTree` 会对**全部坐标做归一化**（`-minX,-minY`），骨线第一点 y 不再是 0；几何断言里凡依赖「骨 y=0」的 regex/截距都失效，须按「两点任意 y + 斜率」解析。
2. 鱼骨括号重叠的两个根因：(a) 兄弟间距少算子树深度（用 `bracketExtent` 而非叶子数）；(b) 宽一级盒把首个三级括号盖住 → 二级起步距离须按一级盒宽预留（`boxSafe`）。
3. 单色骨架（忽略分支跳色）是贴合该截图的关键观感；若要保留逐分支彩色改回 `branchColors` 取色即可。
4. 本机无 numpy（磁盘满装不上），PIL 比对用 `resize` 降采样 + 纯 python 遍历。
